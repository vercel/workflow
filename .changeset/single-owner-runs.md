Experimental single-owner runs. Where the deployment can host a run's owner (a World that implements `invoke`, the current deployment, a static workflow), `start()` marks the run with the reserved attribute `$experimentalSingleOwner` (`'{}'` routes it by its own ID; a caller may pass `{"vercelAffinity": ...}`). Every input — the start, hook resumes, wakes, step results and cancellation — is invoked on one owner, which keeps the workflow resident, validates transitions locally and writes the run's history through one serialized writer. A wide fan-out's steps start as their own `step_created` events commit, instead of after the whole fan-out is created. The owner runs up to three step bodies itself and launches the rest through the queue; their results return through `invoke`. A worker that dies mid-step is redelivered by the queue, and the owner records the lost attempt and retries the step. A queued wake for a run that has ended is acknowledged rather than redelivered. The owner's same-deployment requests (invokes, step delivery and results) run outside the context of whichever request woke it, so the platform's `x-vercel-id` hop chain stays at a constant depth instead of growing with every overflow round trip and tripping loop detection (508); a 508 refusal is retried as an undelivered step. The World contract gains `queue.invoke` and an optional single-writer event session (`events.createWriteSession`).
