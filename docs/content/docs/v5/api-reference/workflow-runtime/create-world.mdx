Creates a new [World](/docs/api-reference/workflow-runtime/world) instance by resolving `WORKFLOW_TARGET_WORLD` from the process environment and invoking that target's factory: the local development World or the Vercel production World by default, or a custom module you name. The target is read from the environment on every call, so a later call can construct a different implementation than an earlier one when the environment has changed. Some framework integrations compile the Local and Vercel World implementations into the server bundle, but that only affects which code is available — selection still happens when the World is created, not at build time.

Unlike [`getWorld()`](/docs/api-reference/workflow-runtime/get-world), which caches a singleton instance, `createWorld()` constructs a fresh instance on every call and does not touch that cache. Changing `WORKFLOW_TARGET_WORLD` therefore does not replace an instance `getWorld()` has already cached; it only affects the next instance that is constructed. Application code should almost always use `getWorld()`. `createWorld()` is for infrastructure code that manages World lifecycles itself.

```typescript lineNumbers
import { createWorld } from "workflow/runtime";

const world = await createWorld(); // [!code highlight]
```

## API signature

### Parameters

This function does not accept any parameters. Configuration comes from the environment of the process creating the World (World implementations typically read their own settings from environment variables when constructed).

### Returns

Returns a `Promise<World>` with a newly constructed World instance.

<Callout type="info">
  Tooling that needs to construct a World with explicit (non-environment) configuration should instantiate the specific World implementation directly and register it with [`setWorld()`](/docs/api-reference/workflow-runtime/set-world).
</Callout>

## Related functions

- [`getWorld()`](/docs/api-reference/workflow-runtime/get-world): Resolve the cached World instance (preferred in application code).
- [`setWorld()`](/docs/api-reference/workflow-runtime/set-world): Override the cached World instance.
