You can build durable workflows in Python using the [`vercel-workflow` SDK](https://pypi.org/project/vercel-workflow/). Your workflow code can pause, resume, and maintain state, just like the JavaScript and TypeScript Workflow SDK.

<Steps>

<Step>

## Configure your Python project

Add the `vercel-workflow` package and workflow entrypoint to `pyproject.toml`:

```toml title="pyproject.toml"
[project]
requires-python = ">=3.12"
dependencies = ["vercel-workflow"]

[[tool.vercel.workflows]]
entrypoint = "app.workflows:wf"
```

The workflow `entrypoint` uses the `module:object` format to point to a [`Workflows`](/docs/api-reference/python/workflows) registry. Define it in `app/workflow.py` now; we'll export it from `app.workflows` later:

```python title="app/workflow.py"
from vercel import workflow

wf = workflow.Workflows(
    sandbox_policy=workflow.SandboxPolicy(share_sandboxes=True),  # [!code highlight]
)
```

`share_sandboxes=True` reuses a sandbox across workflow runs for faster startup. Module globals are shared between those runs, so workflow code should not mutate global state.

</Step>

<Step>

## Create your first workflow

A workflow is a stateful function that coordinates multi-step logic over time. Use the `@wf.workflow` decorator to mark a function as durable:

```python title="app/workflows/ai_content_workflow.py"
from app.workflow import wf
from app.steps.generate_draft import generate_draft, summarize_draft
from vercel import workflow

@wf.workflow  # [!code highlight]
async def ai_content_workflow(*, topic: str):
    draft = await generate_draft(topic=topic)
    await workflow.sleep("5s")
    summary = await summarize_draft(draft=draft)

    return {
        "draft": draft,
        "summary": summary,
    }
```

Now, export the registry from the `app.workflows` package and import the module containing your workflow so its definitions are registered:

```python title="app/workflows/__init__.py"
from app.workflow import wf
from app.workflows import ai_content_workflow

__all__ = ["ai_content_workflow", "wf"]
```

We'll fill in those step functions next. The current code does the following:

* The `@wf.workflow` decorator defines a **workflow** that orchestrates individual **steps**. The SDK records all inputs and outputs in an event log, allowing it to replay execution deterministically after a crash. Learn more in [Workflows and Steps](/docs/foundations/workflows-and-steps?language=py).
* `workflow.sleep()` suspends the workflow without consuming resources. See the [`sleep()` API Reference](/docs/api-reference/python/sleep) for supported duration formats, absolute wake times, and `asyncio.sleep()` support.

</Step>

<Step>

## Create your workflow steps

A step is a stateless function that runs a unit of durable work inside a workflow. Use `@wf.step` to mark a function as a step:

```python title="app/steps/generate_draft.py"
import random
from app.workflow import wf

@wf.step  # [!code highlight]
async def generate_draft(*, topic: str):
    return await ai_generate(prompt=f"Write a blog post about {topic}")

@wf.step  # [!code highlight]
async def summarize_draft(*, draft: str):
    summary = await ai_summarize(text=draft)

    # Simulate a transient error. The step automatically retries.
    if random.random() < 0.3:
        raise Exception("Transient AI provider error")

    return summary
```

Each step executes separately from the workflow orchestrator. While the step executes, the workflow suspends without consuming resources. When the step completes, the workflow resumes automatically where it left off.

</Step>

<Step>

## Starting a workflow

Call [`workflow.start()`](/docs/api-reference/python/start) from server-side code to start a workflow. It returns a [`Run`](/docs/api-reference/python/run) that you can use to identify the run, check its status, and wait for its result:

```python title="app/api/generate.py"
from app.workflows.ai_content_workflow import ai_content_workflow
from vercel import workflow

@app.post("/api/generate")
async def generate_content(*, topic: str):
    run = await workflow.start(ai_content_workflow, topic=topic)  # [!code highlight]

    print(run.run_id)
    print(await run.status())  # [!code highlight]

    # Wait until the workflow completes and return its result.
    return await run.return_value()  # [!code highlight]
```

Starting a workflow only waits until the run has been created and queued. Await `return_value()` to wait for the workflow to finish, or save its `run_id` and recreate the handle later with `workflow.Run(run_id)`. See [Starting Workflows](/docs/foundations/starting-workflows?language=py) for more details.

</Step>
