A run's usage shows where its events come from (which steps and hooks drive them) and how much it stores, counted the way Vercel bills them, so you can estimate a workflow's cost before you deploy it. Usage is available on the Local World.

## See a run's usage

```bash
npx workflow inspect run <run_id> --usage
```

In the web UI, a run's header shows its **Events** and **Storage (local)**. Select either one, or the run's **Usage** tab, to open its Usage page (`/run/<run_id>/usage`), which shows the same table.

`--json` prints the same numbers as JSON. Its shape is experimental and may change.

The output includes hook tokens, and a token resumes its hook. Share it, `--json` included, only where you would share the run's data.

## What's counted

### Events

Every event in the run's log counts once. [Event sourcing](/docs/how-it-works/event-sourcing) describes which events a run, its steps, hooks and sleeps write.

### Storage

**Storage (local)** counts the bytes of the run's payloads as the SDK sent them (compressed when that saves space, and encrypted when encryption is on): run inputs and outputs, step inputs and results, errors, and hook metadata and payloads. It adds the bytes the run wrote to its streams. Event metadata, such as ids and timestamps, isn't counted. A run started with `experimental_retention: 0` reports what it wrote before its data was deleted.

When a run's data is deleted, its sizes stay in the local data directory, so usage can still report them.

Two kinds of data aren't counted locally:

- **QuickJS VM snapshots.**
- **A dynamic workflow's code.**

The numbers describe this run. The same workflow can record a different number of events on another run, for example with more or fewer retries.

## On Vercel

A run's events are its Workflow Events, and **Storage (local)** is counted the way Data Written is, except that Data Written also includes QuickJS VM snapshots and a dynamic workflow's code. Usage doesn't show Data Retained, function compute, or queues; see [Workflow pricing](https://vercel.com/docs/workflows/pricing), and open a run on the Workflows page in the [Vercel dashboard](https://vercel.com/dashboard) for what it was billed.
