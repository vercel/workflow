`experimental_setAttributes` attaches plaintext string metadata to the current workflow run. These attributes can be displayed by observability tools as run tags.

<Callout>
This feature is experimental and may change before the stable attributes API is released.
</Callout>

```typescript lineNumbers
import { experimental_setAttributes } from "workflow"

export async function orderWorkflow(orderId: string) {
  "use workflow"

  await experimental_setAttributes({
    phase: "received",
    orderId,
  })

  // ...work...

  await experimental_setAttributes({ phase: "complete" })
}
```

## Usage

Call `experimental_setAttributes` from a `"use workflow"` function. Calling it from a `"use step"` function or plain application code is not supported.

Values must be strings. Pass `undefined` to remove a key:

{/* @skip-typecheck - snippet, depends on workflow runtime */}

```typescript lineNumbers
import { experimental_setAttributes } from "workflow"

export async function cleanupAttributes() {
  "use workflow"

  await experimental_setAttributes({ staleKey: undefined })
}
```

Attribute keys that start with `$` are reserved for framework and library code.

## Experimental Behavior

While attributes are experimental:

- Worlds that do not support attributes log a warning and ignore the call.
- Storage errors are logged after retries, but do not fail the workflow run.
- Setting attributes is currently slower than the final API will be, because each write goes through an internal workflow step. Prefer batching related tags in one call.

In a future release, using attributes with a World that does not support them, or when the World fails to store them, will fail with a [world error](/docs/api-reference/workflow-errors/workflow-world-error).
