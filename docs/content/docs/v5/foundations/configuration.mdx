Workflow is configured through two surfaces:

- **Framework plugin options** — typed options on your framework integration, like [`withWorkflow()`](/docs/api-reference/workflow-next/with-workflow) for Next.js, or the World factory functions like `createWorld()`.
- **Environment variables** — everything else, and per-environment overrides.

When both exist for the same setting, the precedence is always:

```
explicit option (plugin / factory argument)  >  environment variable  >  built-in default
```

Invalid environment variable values never crash the app — they log a warning and fall back to the default (clamped values note the clamp in the tables below).

## Choosing a World

The [World](/docs/deploying) is the backend that stores runs and delivers queue messages. Select it with:

### `WORKFLOW_TARGET_WORLD`

| Value | World |
| --- | --- |
| `local` | [Local World](/docs/deploying/world/local-world) (alias for `@workflow/world-local`) |
| `vercel` | [Vercel World](/docs/deploying/world/vercel-world) (alias for `@workflow/world-vercel`) |
| `@workflow/world-postgres` | [Postgres World](/docs/deploying/world/postgres-world) |
| any package specifier | A custom World package |

Default: `vercel` when running on Vercel (`VERCEL_DEPLOYMENT_ID` is set), otherwise `local`.

Each World has its own configuration — connection strings, data directories, auth — documented on its page:

- [Local World configuration](/docs/deploying/world/local-world#configuration) — `WORKFLOW_LOCAL_DATA_DIR`, `WORKFLOW_LOCAL_BASE_URL`, `PORT`, ...
- [Postgres World configuration](/docs/deploying/world/postgres-world#configuration) — `WORKFLOW_POSTGRES_URL`, worker concurrency, pool size, ...
- [Vercel World configuration](/docs/deploying/world/vercel-world#configuration) — auth token and project targeting for tooling.

## Runtime

These variables tune the workflow runtime (`@workflow/core`). They are read where your workflows execute — set them on the deployment (or dev server), not just in your shell.

| Variable | Controls | Default |
| --- | --- | --- |
| `WORKFLOW_REPLAY_TIMEOUT_MS` | Budget for the deterministic-replay portion of a single handler invocation. Inline step bodies don't count against it. | `240000`, clamped to `30000`–`780000` |
| `WORKFLOW_REPLAY_TIMEOUT_MAX_RETRIES` | Queue deliveries that may hit the replay timeout before the run is failed with `REPLAY_TIMEOUT`. | `3` |
| `WORKFLOW_MAX_QUEUE_DELIVERIES` | Delivery attempts before a run/step is failed gracefully. Can only be lowered — the default is calibrated so failure is recorded before the queue expires the message. | `48` |
| `WORKFLOW_V2_TIMEOUT_MS` | Inline step-execution budget within one invocation; once elapsed, remaining steps are queued instead of run inline. | `120000` |
| `WORKFLOW_MAX_INLINE_STEPS` | How many newly-created steps one invocation runs inline (in parallel) before queueing the rest. `1` restores strictly sequential inline execution. | `3`, clamped to `1`–`16` |
| `WORKFLOW_TURBO` | Fast path for a run's first delivery: backgrounds the `run_started` event and skips the event-log load. Set `0`/`false` to disable. | enabled |
| `WORKFLOW_OPTIMISTIC_INLINE_START` | Start inline step bodies before their `step_started` event is confirmed. Unsafe for non-idempotent side effects if handlers race; `WORKFLOW_TURBO` already applies it where it's safe. | disabled |
| `WORKFLOW_TRACE_MODE` | OpenTelemetry span topology for runs: `linked` or `continuous`. | `linked` |
| `WORKFLOW_DISABLE_COMPRESSION` | `1` disables compression when writing payloads (reads still decompress). | compression on |
| `WORKFLOW_COMPRESSION_CODEC` | Force the write-side codec: `zstd` or `gzip`. | automatic (`zstd` when available, else `gzip`) |
| `WORKFLOW_QUEUE_NAMESPACE` | Prefix for queue topics (`__wkf_*` → `__<ns>_wkf_*`) so multiple apps can share queue infrastructure. Must match `^[a-z][a-z0-9]*$`. Read at build time and by the World at runtime — set it in both places. | none |
| `DEBUG` | Debug log filter with wildcards and negation, e.g. `workflow:*` or `workflow:*,-workflow:telemetry:*`. | unset |

### Advanced tuning

Escape hatches you should rarely need; listed for completeness.

| Variable | Controls | Default |
| --- | --- | --- |
| `WORKFLOW_STREAM_FLUSH_INTERVAL_MS` | Stream write buffering interval. | `10` |
| `WORKFLOW_FRAMED_STREAM_MAX_RECONNECTS` | Consecutive reconnect cap for framed stream readers. | `50` |
| `WORKFLOW_FRAMED_STREAM_MAX_TOTAL_RECONNECTS` | Total reconnect cap per stream session. | `1000` |
| `WORKFLOW_WAIT_CONTINUATION_MAX_DELAY_SECONDS` | Longest single queue delay used for `sleep()`; longer sleeps chain messages. | `82800` (23h) |
| `WORKFLOW_NEAR_ELAPSED_WAIT_THRESHOLD_SECONDS` | Clock-skew tolerance when resuming waits. | `2` |
| `WORKFLOW_REPLAY_DIVERGENCE_MAX_RETRIES` | Recovery replays before a replay divergence is recorded as corruption. | `3` |
| `WORKFLOW_DEFERRED_CHECK_DELAY_MS` | Delay before the unconsumed-event check fires. | `100` |
| `WORKFLOW_LOCK_POLL_INTERVAL_MS` | Poll interval for detecting stream lock release. | `10` |

## Build

Read by the compiler/builders (`@workflow/builders` and the framework integrations) when your app is built:

| Variable | Controls | Default |
| --- | --- | --- |
| `WORKFLOW_SOURCEMAP` | Source maps for generated workflow bundles: `true`, `inline`, `linked`, `external`, `both`, `false` (plus `1`/`0`). The framework plugin `sourcemap` option takes precedence. | `inline` in development, `false` in production |
| `WORKFLOW_PUBLIC_MANIFEST` | `1` exposes the workflow manifest at `/.well-known/workflow/v1/manifest.json`. | disabled |
| `WORKFLOW_DEV_HMR_LOGS` | `1` logs workflow rebuild activity during `next dev`, for diagnosing watch/HMR issues. | disabled |

<Callout type="info">
The legacy `WORKFLOW_EMIT_SOURCEMAPS_FOR_DEBUGGING=1` variable still works but is narrower than `WORKFLOW_SOURCEMAP`; prefer the latter. See [source maps in `withWorkflow()`](/docs/api-reference/workflow-next/with-workflow#source-maps).
</Callout>

## CLI and observability

The `workflow` CLI and web UI infer their configuration automatically — the data directory for the Local World, and project/team/auth (from your `.vercel` directory and Vercel CLI login) for the Vercel World. The same values can be pinned explicitly with the [per-World variables](/docs/deploying/world/vercel-world#configuration) or CLI flags like `--backend`, `--project`, and `--env`.

| Variable | Controls | Default |
| --- | --- | --- |
| `WORKFLOW_NO_UPDATE_CHECK` | `1` disables the CLI's update check. | check enabled |

Anything not listed on this page or a World page (for example `WORKFLOW_NEXT_PRIVATE_BUILT` or `WORKFLOW_SOCKET_*`) is internal to the SDK — don't set it.
