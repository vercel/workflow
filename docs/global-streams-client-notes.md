# Global streams: client contract notes

This SDK exposes global streams separately from run streams. The server contract leaves several decisions visible to callers and reviewers:

- **The encryption envelope is immutable.** Every chunk write carries `X-Stream-Encryption`, the base64url encoding of canonical JSON. The server conditions index reservation on an exact match and rejects a mismatch before reserving an index or persisting bytes. Core retains the plaintext framed write, reloads `/info`, re-encrypts, and retries once on `stream_encryption_mismatch`. Close carries no envelope because it writes no bytes.
- **The envelope scheme is an open set.** This client implements only `{"v":1,"s":"dpl","d":"dpl_…","k":"…"}`. Unknown versions or schemes fail loudly rather than being treated as unencrypted data. The complete envelope travels with the stream ID in the distinct `GlobalWritableStream` descriptor.
- **Unwritten streams have no readable state.** The server returns 404 until the first write. The SDK surfaces that response rather than treating it as an empty live stream: silently waiting would make a typo indistinguishable from a stream not yet created. `getInfo()` therefore also rejects for an unwritten ID.
- **Retention races.** `earliestIndex` is advisory: a chunk may expire after `/info` or during a live read. A 410 is terminal for that read session and is exposed; reconnecting cannot recover absent bytes. Applications should persist their own cursor and handle retention expiry.
- **Minting requires a region.** Random IDs are minted by the World so world-vercel can reuse its region-tagged ULID scheme. `globalStreamIdFor({ region, name })` uses a version-2 tagged body derived from `SHA-256(projectId|environment|name)`; the server never sees the name. Worlds without the matching ID capability reject instead of minting an unroutable ID.
- **Public-key authenticity and key rotation.** Before using local deployment key material, core derives its X25519 public key and compares it with envelope field `k`. It uses the symmetric shortcut only on a match; otherwise it fails rather than silently writing under stale BYOK material. Off-anchor writers hold only `k` and seal (`encp`).
- **Run-key API terminology and controls.** Cross-deployment global-stream readers use the existing run-key endpoint with a `gstr_` ID. Its rate limits, auditing, and errors may refer to a “run”; server/API owners should confirm that this use is supported and observable without misleading operators.
- **SDK layering.** `@workflow/world-vercel` cannot derive X25519 keys because core depends on it. Core therefore constructs and validates the envelope while the World adapter canonicalizes and transports it. This keeps package dependencies acyclic and makes alternate encryption schemes a core concern rather than a Vercel transport concern.
