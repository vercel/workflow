## How to use

Each table has four columns:

1. **Canonical (Title Case)** — use in buttons, labels, titles, table column headers, modal titles, page headings, navigation, badges.
2. **Body-prose form** — use in body text, errors, toasts, tooltips, placeholders, helper text, validation messages, and inline links.
3. **Banned variants** — never ship these in user-facing copy.
4. **Source-of-truth file** — where the noun’s full behavior is documented.

The lock marker **🔒** after a canonical term means **preserved casing in body** — the term keeps its Title Case form even in body prose, errors, toasts, and helper text. Without 🔒, the term takes sentence-case flexion in body (Title Case in buttons/titles, lowercase in prose).

Billing line items (`Active CPU`, `Fast Data Transfer`, `Function Invocations`, etc.) are billing taxonomy, not UI nouns.

For terms not yet in this file, apply the [Capitalization Rules of Thumb](#capitalization-rules-of-thumb) below; when those don’t resolve it, match shipped adjacent copy.

> **🔒 lock is for Vercel-coined product names. Industry-generic categories aren’t locked.** `Skew Protection` 🔒, `Deployment Protection` 🔒, `Password Protection` 🔒 — Vercel invented these labels; they’re proper nouns in body. `identity provider`, `verified commits`, `webhook`, `cron jobs`, `Git provider`, `payment method` — these are industry concepts that Vercel exposes a setting for; they’re lowercase in body. The setting label that wraps an industry concept can still be Title Case in headings (`Require Verified Commits`, `Identity Provider Connection`); the concept itself flexes to lowercase in surrounding prose. **Litmus test:** if Okta, AWS, GitHub, or Stripe also have this concept under the same name, it’s probably industry-generic — don’t lock it.

> **Legacy term coexistence.** When shipped adjacent code uses a LEGACY term (`Edge Function`, `Edge Middleware`, `Vercel Analytics`, `Preview Mode`), leave it for consistency unless the entire surface is being rewritten. The canonical (`Vercel Function on the Edge Runtime`, `Routing Middleware`, `Web Analytics`, `Draft Mode`) applies to NEW copy on a fresh surface; rewriting one string in isolation creates internal inconsistency that costs more than the drift it fixes. Spot-check shipped UI before rewriting (`git grep -i 'Edge Function' apps/vercel-site/`).

Experiment terms describe one analysis. The source of truth is the analysis SQL in `vercel/api` (`services/api-web-analytics/src/experiments/compile-exposures.ts`). Every unit count is one of three nested sets: exposed units include enrolled units, which include analyzed units. Always name the set: never label an experiment count `Units` alone.

- **Unit**: what gets a variant, such as a visitor, a user, or a team. The experiment's unit field names the ID to use. Use `unit`, not `entity`, in experiment copy.
- **Variant**: what the unit was served. It does not tell if the unit is in the experiment. That is the enrollment.
- **Exposure**: a record that a unit was served a variant of the experiment flag, for any reason. Each exposure has an assignment reason.
- **Assignment reason**: why the unit got its variant. The Flags SDK records one reason on each exposure. By default, each evaluation of a flag that has an experiment makes an exposure, also when the experiment did not choose the variant. Only a random assignment from the current ramp enrolls the unit. The other exposures keep the current ramp ID, so they contaminate a unit that is already enrolled. The SDK value is in parentheses:
  - `Enrolled` (`experiment`): the experiment chose the variant at random, with the variant weights.
  - `Override` (`override`): an override set the variant, for example from Flags Explorer. The app reports the override when it applies it.
  - `Outside Ramp` (`not-enrolled`): the experiment is the outcome, but the unit is not in the ramp percentage, or the unit has no ID. The unit gets the experiment's default variant.
  - `Targeted` (`targeted`): the unit is in one of the flag's target lists for this environment. Target lists come before rules.
  - `Fixed Variant` (`variant`): a rule, the environment's default, or a paused environment served one fixed variant. Before an experiment starts, every exposure can have this reason.
  - `Split` (`split`): a rule or the environment's default served a weighted split of variants that is not the experiment.
  - `Rollout` (`rollout`): a rule or the environment's default served a progressive rollout between two variants.
  - `Earlier Ramp` (`experiment`, from an earlier ramp): a random assignment from a ramp that is not the current one. The SDK does not send this reason. The dashboard compares the ramp IDs.
  - `—` (no reason): the exposure has no reason, so it tells nothing about enrollment. It does not enroll the unit, but it can contaminate it.
- **Ramp**: one analysis period, and only the current ramp counts. A decrease of the allocation, a reseed of a running experiment, or a change to the weights of a running experiment starts a new ramp. An increase of the allocation and a change of the control keep the current ramp. In UI copy, say that a change restarts or keeps the analysis, and add `Results only include data from this change on.` when it restarts. Do not say `epoch`.
- **Exposed units**: units with at least one exposure, for any reason.
- **Enrolled units**: units with at least one random assignment in the current ramp. The sample ratio check counts all enrolled units.
- **Contaminated units**: enrolled units that got a second variant, or a non-random exposure at or after their first random assignment. The unit stays in its first variant.
- **Analyzed units**: the enrolled units that the analysis keeps. That is all enrolled units, or enrolled units minus contaminated units when the experiment excludes contaminated units. Metric results and the units chart count analyzed units.
- **Metric event**: a Web Analytics custom event that a metric counts. It has no variant of its own: it gets the variant of its unit's exposure.
- **Enrollment**: the status of one exposure. Show an `Enrolled` or `Not Enrolled` badge, then the reason in plain text. Add `Contaminates Unit` when the data proves it.

Experiment Health, on the Analysis tab, shows four checks and three verdicts. The server computes the sample ratio check, and the dashboard does not compute its statistics again. The sources of truth are `endpoints/experiments/health.ts` and `statistics.ts` in `vercel/api` (`services/api-web-analytics/src/`), and `_lib/experiment-health.ts` in the dashboard.

- **Population Observed**: each variant with a weight above 0 has enrolled units and analyzed units, and the counts agree. Analyzed units are enrolled units minus the excluded contaminated units, and each metric counts the same units as its variant. The results must also match the configured analysis: ramp, time window, control variant, and contamination policy. Statuses: `Observed`, `Insufficient Data`, `Review Needed`.
- **Sample Ratio Mismatch** (SRM): compares the enrolled units of each variant with the configured variant weights. A chi-square goodness-of-fit test gives a p-value, and a p-value below 0.01 is a mismatch. Units in a variant with a weight of 0 are always a mismatch. The check needs at least two variants with a weight above 0, and at least 5 expected units for each. It counts all enrolled units, also the contaminated ones. A mismatch usually means that assignment or exposure collection is broken, so do not trust the results. Statuses: `Passed`, `Mismatch Detected`, `Insufficient Data`, `No Data`, `Invalid Allocation`, `Unavailable`.
- **Contamination**: counts the contaminated units and states the contamination policy. More than 0 needs a review, but it is not a failure. Statuses: `None Observed`, `Review Needed`, `Insufficient Data`, `Unavailable`.
- **Measurement Quality**: always `Not Assessed`. It tells that the checks do not cover identity quality, event correctness, collection completeness, or data freshness.
- **Data Health** (verdict): `Checks Passed` when Population Observed and Sample Ratio Mismatch pass and no unit is contaminated. `Review Needed` when a check fails or units are contaminated. `Insufficient Data` when a check needs more data.
- **Decision Readiness** (verdict): `Results Ready` when Data Health passes and the server reports at least one significant comparison for the primary metric. `Inconclusive` when no comparison is significant. `Review Data`, `Insufficient Data`, or `Unavailable` otherwise. It never means that the change is ready to ship.
- **Metric Impact** (verdict): the direction of the significant primary metric comparisons, from their confidence intervals: `Increase Detected`, `Decrease Detected`, `Mixed Changes`, `No Clear Change`, or `Unavailable`. It does not tell if the change is good. Review guardrail metrics separately.

## Capitalization Rules of Thumb

When a noun is not in the table, fall back to these rules in order:

1. **🔒-marked Vercel brand names** stay capitalized in body. The lock indicator means the term is a proper noun for a Vercel product, surface, or feature; preserve the Title Case form in body prose, errors, toasts, helper text, and validation messages.
2. **Plan tier names** (`Hobby`, `Pro`, `Enterprise`) stay Title Case in body. They are proper nouns of the billing system.
3. **Environment names** (`Production`, `Preview`, `Development`) stay Title Case in body when they label an env scope. Lowercase in casual prose ("deploy to production").
4. **Role names** (`Owner`, `Admin`, `Developer`, `Viewer`) sentence-case in body, Title Case in role labels and chips.
5. **Stable-identifier prefixes** (`dpl_…`, `bld_…`, `cfg_…`, `key_…`) match the prefix to the label. `Deployment ID: dpl_…` is correct; `Request ID: dpl_…` is the most common drift bug.
6. **Status enum values** match the API enum verbatim (Title Case in product surfaces). When the API uses `Canceled`, the UI uses `Canceled`; do not Anglicize to `Cancelled` (Workflow’s `Cancelled` is the documented exception).
7. **Drain types** (`Log Drain`, `Trace Drain`, `Speed Insights Drain`, `Web Analytics Drain`) name a schema under the `Drains` umbrella; capitalize as a feature label and lowercase as a descriptive instance.
8. **Acronyms with full forms** (BYOK, MCP, ISR, RES, VES, WAF) spell out on first reference, then use the acronym after.
9. **When in doubt, match shipped adjacent copy** in the file you’re editing. The constants file (`components/.../constants.ts`) is the tiebreaker.
